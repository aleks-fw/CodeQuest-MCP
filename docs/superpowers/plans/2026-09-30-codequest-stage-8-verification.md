# CodeQuest MCP — этап 8: проверка выполнения

Спек §8. Ветка `stage-8`. Пишу и проверяю сам, без субагентов.

## Что сделано (`src/verification/`)

- `evidence.ts` — что видят условия: свежий анализ (`analyzeWithContext` отдаёт снимок и контекст), изменённые файлы,
  запуски команд. Запуск засчитывается, только если его `changeKey` равен текущему.
- `criteria.ts` — семь условий §8.1 (`evaluateCriterion`). Условие, которое не выполнено из-за пропавшего файла, несёт
  `missing: true` (нужно для «квест неактуален»).
- `changed.ts` — файлы, изменённые после появления квеста: git diff от запомненного HEAD плюс новые файлы; вне git — по
  времени изменения; не удалось — `null`, и тогда изменёнными считаются все файлы.
- `commands.ts` — запуск test/lint/build: `CI=1`, `FORCE_COLOR=0`, оболочка, таймаут 30–1800 с (по умолчанию 300) с
  завершением дерева процессов, последние 50 строк, «модуль не установлен» = команда недоступна.
- `verify.ts` — `verifyQuest` (выполнен / неактуален / открыт, эпик из подзадач), `autoDue` (когда автопроверка), 
  `neededCommands` (какие команды запускать), признак `scriptChanged` (V = 0,8).

## Решения при реализации

- `movedLinesShare` (Split Large File): файл сократился минимум на половину, а проект потерял не больше 25% строк
  файла — иначе «код удалён, а не перенесён».
- Подзадачи эпика проверяются по одной; эпик выполнен, если сделана хотя бы одна подзадача и открытых не осталось.
  Неактуальные подзадачи эпик не блокируют; если сделано ноль — эпик неактуален.
- Кто и когда вызывает проверку, пишет события и начисляет XP — этап 9 (engine). Здесь только чистые проверки и запуск.
