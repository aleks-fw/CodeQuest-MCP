# CodeQuest MCP — этап 5: хранилище

Спек §5. Ветка `stage-5`. Пишу и проверяю сам, без субагентов (решение пользователя: экономить лимиты).

Модули `src/storage/`:

- `paths.ts` — папка данных: `--home`, потом `CODEQUEST_HOME`, потом `~/.codequest`; имена файлов проекта.
- `atomic.ts` — запись JSON через временный файл и переименование (повтор при `EPERM`/`EBUSY` на Windows), чтение с
  различием «нет файла» и «файл повреждён».
- `lock.ts` — `.lock` с pid, временем и токеном; устаревает через 30 с; ожидание до 10 с с повтором каждые 50 мс;
  снимает только свою блокировку.
- `journal.ts` — `events.jsonl`: только дописывается, номера с 1, оборванная строка пропускается, сумма XP.
- `store.ts` — `ProjectStore` (запись проекта, кэш снимка, `state.json` с восстановлением из журнала), `openProject`
  (тот же номер проекта после переноса папки), профиль.

Типы `GameEvent`, `ProjectRecord`, `Profile` — в `src/types.ts`.

Договорённости:

- Время передаётся параметром (`at`), кроме блокировки: ей нужны часы, их можно подменить в тестах.
- Уровень по XP считает вызывающий код (`levelForXp`): формула уровней — этап 6.
- Записи в один проект делаются внутри `store.withLock`; `appendEvents` нумерует события по файлу и не защищён сам.
- Тесты пишут только в `<repo>/.tmp/` на диске D.

Проверка: `npm run check`, коммит на ветке `stage-5`, статус этапа в `ПЛАН.md` и дорожной карте.
