началом, когда предыдущий этап закоммичен и одобрен: так он опирается на реальный код, а не на догадки.

## Сквозные договорённости (действуют во всех планах)

- Модель данных — `src/types.ts` (создаётся в этапе 1 по спеку §5). Новые поля добавляются туда же, а не в модули.
- `game/` и `hud/` — чистые функции: без `node:fs`, `node:child_process`, без `Date.now()`; время передаётся параметром.
- `server/`, `tools/`, `cli/` импортируют только `engine/`, `hud/` и `types.ts`.
- Импорты внутри проекта — с расширением `.js` (ESM, `NodeNext`).
- Временные папки тестов — только в `<repo>/.tmp/` (диск D), имя с пробелом и кириллицей; `.tmp/` в `.gitignore`.
- Проверка в конце каждого этапа: `npm run check` (tsc --noEmit, biome check, vitest run), локальный коммит, отчёт.
- Установка пакетов, push, регистрация MCP, изменение настроек — только после «да» пользователя.

## Отклонение от спека

- Спек §2.5: «Node ≥ 20». Vitest 5 требует Node `^22.12 || ^24 || >=26`, поэтому `engines.node` = `>=22.12`.
  У пользователя Node 24.19 — на работу не влияет.
