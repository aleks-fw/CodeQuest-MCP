# CodeQuest: история проекта (фаза 2, часть 1)

Дата: 2026-10-02. Родительский документ: `2026-09-28-codequest-design.md` (§5 журнал событий, §9.6 уведомления).

## 1. Цель

Дать таймлайн проекта из журнала событий: что было сделано и когда, по дням, с итогом дня. Читается как летопись, а не как
лог. Для кого: пользователь через Claude (MCP-инструмент) и сам Claude, когда нужно напомнить, что уже сделано.

Критерий готовности: `get_project_history` на проекте с несколькими днями работы отдаёт дни сверху вниз; у каждого дня —
итог (XP, число закрытых квестов, смена уровня) и вехи по времени; шума (анализы, открытие квестов, неудачные проверки)
нет; текст на языке из настроек.

Не входит: отдельная команда CLI, фильтры по категориям, экспорт, графики, любое новое хранилище (всё считается из
журнала).

## 2. Что попадает в историю

Только вехи. Из событий журнала:

| Событие | Строка |
|---|---|
| `quest_completed` | ✓ название · +XP (XP из данных события) |
| `xp` с полем `topUp` | + XP · название: подтверждено зелёным прогоном команд проекта (готовый текст `notif.topup`) |
| `level_up` | ⚔️ УР. a → b · титул (готовый текст `notif.levelup`) |
| `finding_returned` | ↩ вернувшаяся проблема (готовый текст `notif.returned` и `notif.returnedIn`) |
| `settings_changed` | команды проекта разрешены / не разрешены, таймаут |

Обычные события `xp` (без `topUp`) не показываются: их сумма уже есть в `quest_completed`. Остальные типы событий
(`analysis`, `quest_opened`, `quest_accepted`, `quest_released`, `quest_obsolete`, `epic_progress`, `verification_failed`)
в историю не входят.

## 3. Итог дня

- XP дня: сумма `xp` из `quest_completed` и `amount` из доплат (`topUp`).
- Закрыто квестов: число `quest_completed` за день.
- Уровень: если в день был `level_up`, показывается `УР. from первого → to последнего`.
- День без вех не показывается. Части итога, равные нулю, в заголовке дня не показываются (день только со сменой настроек — одна дата).

Границы дня — по местному времени компьютера (`Date` в часовом поясе процесса). Время события — `ЧЧ:ММ` местное.

## 4. Устройство

- `src/game/history.ts` — чистая функция `buildHistory(events, { days, now }) → HistoryDay[]`. Без чтения файлов и без
  языка. `HistoryDay = { date: 'YYYY-MM-DD', xp, quests, levelFrom?, levelTo?, entries: HistoryEntry[] }`;
  `HistoryEntry = { event: GameEvent, time: 'ЧЧ:ММ' }`. Дни от новых к старым, внутри дня — от новых к старым. Берутся дни,
  входящие в окно `days` (по умолчанию 14, от 1 до 365) назад от `now`.
- `src/hud/history.ts` — `historyText(days, lang) → string` и `historyLine(event, lang)`. Строки событий собираются из
  существующих `notificationLine` и каталога `t`; новые ключи — только для заголовка дня, итога и смены настроек.
- `Engine.history(request, days)` — читает `events.jsonl` проекта (`readEvents`), без блокировки (журнал только
  дописывается, битая последняя строка пропускается), возвращает `{ project, lang, days }`.
- `src/tools/register.ts` — инструмент `get_project_history` (`project_path?`, `days?`, только чтение). Текст — как в
  разделе 5, `structuredContent` — `{ project, days: HistoryDay[] }` с уже отрисованными строками.

## 5. Вывод

```
ИСТОРИЯ · <проект> · за 14 дн.
2026-10-02 · +171 XP · 1 квест · УР. 2 → 3
  11:23 + 95 XP · Remove Hardcoded Secret: подтверждено зелёным прогоном команд проекта
  11:21 ✓ Remove Hardcoded Secret · +76 XP
  09:40 ⚔️ LEVEL UP 2 → 3 · <титул>
```

Пустая история: «За этот период вех нет.»

## 6. Ошибки и граничные случаи

- `days` вне 1–365 приводится к границе, а не отвергается.
- Старые события без `template`/`vars` показывают сохранённое английское название (так уже работает `titleOf`).
- Нет журнала — пустая история, не ошибка.
- Проект не найден — обычная локализованная ошибка (`error.pathMissing`).

## 7. Тесты (TDD)

1. `buildHistory`: группировка по дням, порядок, итог дня (XP, квесты, уровень), фильтр лишних типов, окно `days`,
   день без вех пропускается, обычное `xp` не считается второй раз.
2. `historyText`: русский и английский вывод, пустая история, событие со старыми данными без шаблона.
3. Движок: история проекта после реального цикла (закрытый квест, доплата).
4. MCP-клиент: вызов `get_project_history` с `days` и без; значение вне границ.
5. Каталоги: у каждого нового ключа есть ru и en.
