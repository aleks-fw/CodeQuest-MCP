# CodeQuest: достижения (фаза 2, часть 2)

Дата: 2026-10-02. Родитель: `2026-09-28-codequest-design.md` (§5 журнал, §9.6 уведомления); соседняя часть: `2026-10-02-codequest-history-design.md`.

## 1. Цель

Постоянные отметки о реальных вехах проекта: «первый закрытый квест», «десять квестов», «первый зелёный прогон» и т. п. Это память о вехе, а не награда: XP достижения не дают, формулы XP и уровней не меняются.

Критерий готовности: когда веха достигнута, в журнале один раз появляется событие `achievement_unlocked`; пользователь видит строку в уведомлениях и в истории; `get_achievements` показывает все 12 достижений — полученные с датой, остальные с прогрессом; тексты на ru и en; уже заработанное раньше открывается задним числом.

Не входит: XP за достижения, скрытые достижения, достижения по статам и по состоянию проекта, общий профиль достижений по всем проектам (у каждого проекта свои), отдельная команда CLI.

## 3. Как работает

- `src/game/achievements.ts` — `ACHIEVEMENTS: AchievementDef[]` (`id`, `goal`, `value(counters) → number`) и `counters(events) → Counters`: закрыто всего, по категориям, `maxLevel`, `green` (есть ли подтверждённый зелёным прогоном квест или доплата), число `secret`, `hard`, `epic`. События принимаются как `Pick<GameEvent, 'type' | 'data'>`, чтобы считать и события текущего цикла, у которых ещё нет `seq`.
- `evaluate(events) → AchievementStatus[]`: для каждого достижения `{ id, value, goal, unlockedAt? }`; `unlockedAt` — `at` события `achievement_unlocked` с этим `id` (первого, если их несколько).
- `newlyUnlocked(events, at) → NewEvent[]`: события `achievement_unlocked` (`data: { id }`) для достижений, у которых `value >= goal` и ещё нет события с этим `id`. Повторный вызов на журнале с уже записанными событиями возвращает пустой список.
- `src/engine/cycle.ts`: перед `appendEvents` в конце полного цикла к `events` добавляется `newlyUnlocked([...loaded.events, ...events], at)`. Быстрый путь (кэш без изменений) ничего не пишет; поэтому заработанное раньше откроется при первом полном цикле: после изменения кода, по V или по R. Дата получения такого достижения — дата открытия, а не дата самой вехи.
- `Engine.achievements(request)` читает журнал (как `Engine.history`: без цикла, без блокировки) и возвращает `{ project, lang, items: AchievementStatus[] }`.

## 4. Где видно

- Уведомление (`notificationLine`): `🏆 Достижение: <название> — <описание>` / `🏆 Achievement: <name> — <description>`. Действуют общие правила: не больше 5 строк, остальное «+N ещё».
- История: `achievement_unlocked` становится шестой вехой (`isMilestone`), строка в истории совпадает со строкой уведомления.
- MCP-инструмент `get_achievements` (`project_path?`, только чтение):

```
ДОСТИЖЕНИЯ · <проект> · 3/11
🏆 Первый шаг · Закрыть первый квест · 2026-10-02
🔒 Десяток · Закрыть 10 квестов · 7/10
```

  `structuredContent`: `{ project, unlocked, total, items: [{ id, name, description, value, goal, unlockedAt? }] }`. Порядок: сначала полученные (свежие выше), потом остальные в порядке каталога.

## 5. Ошибки и граничные случаи

- События с неверными типами данных (`xp: "lots"`, `to: null`) считаются нулём и не ломают подсчёт.
- Квест без `category` или с неизвестной категорией считается в «закрыто всего», но не в разнообразие категорий.
- Журнала нет: все достижения не получены, `value` 0.
- `achievement_unlocked` для `id`, которого нет в каталоге (из будущей версии): в `get_achievements` не показывается, в историю и уведомления попадает (название берётся из каталога, а при его отсутствии — сам `id`).
- Повторный полный цикл подряд ничего не пишет (идемпотентность).

## 6. Тесты (TDD)

1. `counters`: закрыто всего, по категориям, `maxLevel`, `green` (по `factor` 1 и по доплате), `secret`/`hard`/`epic`; неверные типы данных.
2. `evaluate`: значения и цели всех 11 достижений; `unlockedAt` из события.
3. `newlyUnlocked`: ровно на пороге (9 квестов — нет, 10 — да), только новые, повторный вызов пуст, события текущего цикла без `seq` учитываются, задний счёт на старом журнале.
4. Цикл (движок на фикстуре): закрытие квеста пишет `first-quest` один раз; следующий цикл ничего не добавляет; старый журнал без событий открывает заработанное при первом полном цикле.
5. Уведомление и история: строка на ru и en; неизвестный `id`.
6. Инструмент `get_achievements` через MCP-клиент: список, прогресс, порядок, число полученных.
7. Каталоги: у каждого ключа `achievement.*` есть ru и en с одинаковыми плейсхолдерами.
8. Тесты, которые перечисляют инструменты по именам (`tests/server/server.test.ts`, `tests/server/tools.test.ts`), обновляются на новое число.
