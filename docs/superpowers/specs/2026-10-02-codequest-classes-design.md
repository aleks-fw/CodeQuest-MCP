# CodeQuest: классы (фаза 2, часть 3)

Дата: 2026-10-02. Родитель: `2026-09-28-codequest-design.md`; соседние части: `...-history-design.md`, `...-achievements-design.md`. План фазы 2 — `ПЛАН.md` §5.

## 1. Цель

Класс проекта — название, которое складывается из того, какую проверенную работу в нём делали больше всего: Architect, Tester, Guardian, Optimizer, Cleaner, Bug Hunter или гибрид. Это отражение того, что уже сделано, и подсветка соответствующих статов. Класс ничего не запрещает и ничего не меняет в игре.

Критерий готовности: у проекта с достаточной проверенной работой в HUD и в `get_project_state` виден класс, у статов класса стоит звёздочка; у проекта без нужного количества работы всё выглядит как раньше; класс считается из журнала налету, ничего нового не хранится; тексты на ru и en.

Не входит: влияние на вес квестов на доске, бонусы XP, уведомление о смене класса, отдельный инструмент `get_class`, классы Builder и Researcher (для них пока нет категорий квестов: появятся вместе с квестами про новые функции и исследования), общий класс разработчика по всем проектам.

## 2. Как считается

Источник — события журнала `quest_completed`. Каждый квест учитывается один раз по `id` (квест, закрытый повторно после возврата проблемы, — тот же квест; событие без `id` считается отдельным). Работа с неизвестной или не относящейся к классам категорией не учитывается совсем.

Категория → класс:

| Класс | Категории |
|---|---|
| Architect | `architecture` |
| Tester | `testing` |
| Guardian | `security`, `reliability` |
| Optimizer | `performance` |
| Cleaner | `cleanup`, `refactoring`, `maintainability` |
| Bug Hunter | `bug` |

Вес квеста — базовая награда за сложность из `BASE_XP` (Easy 100, Medium 300, Hard 500, Epic 1200), без уменьшения за уровень: XP падает с ростом уровня и искажал бы доли. Вес класса — сумма весов его квестов, доля — вес класса, делённый на сумму весов всех учтённых квестов.

- Порог: пока учтено меньше 3 квестов, класса нет.
- Основной класс — с наибольшей долей; при равных долях побеждает тот, что выше в таблице.
- Гибрид: если у второго по величине класса доля не меньше 60% от доли основного и не меньше 20% от всего, класс — гибрид из двух. Третий и дальше в название не входят.
- Название гибрида — «A + B» (в порядке долей); Architect + Tester в любом порядке — **Test Architect** (по ТЗ).

## 4. Устройство

- `src/game/classes.ts` — чистые функции без языка: `CLASSES` (id, категории, статы), `classOf(events) → PlayerClass | null`, где `PlayerClass = { primary: ClassId; secondary?: ClassId; shares: ClassShare[]; stats: (keyof Stats)[] }`, `ClassShare = { id: ClassId; share: number }` (доля 0..1, по убыванию, только ненулевые). События принимаются как `{ type; data? }` (подходят и события журнала, и события текущего цикла без `seq`).
- `src/engine/cycle.ts`: на быстром пути класс считается из журнала, на полном — из журнала вместе с событиями этого цикла; результат цикла получает поле `playerClass`; `ProjectView.playerClass: PlayerClass | null` (в режиме «занято, последнее сохранённое» — `null`, как у `owed`).
- `src/hud/classes.ts` — `className(player, lang)` (название класса или гибрида), `classLine(player, lang)` (строка «Класс: Test Architect (Tester 48% · Architect 36%)»).
- `src/hud/hud.ts`: `formatHud(xp, stats, lang, playerClass?)` добавляет в первую строку ` · <название класса>` и звёздочки у статов класса, которые есть в HUD (Architecture, Testing, Security, Performance, Clean Code, Bugs). Без класса вывод побайтно такой же, как сейчас. `formatMinimal` не меняется.
- `src/hud/report.ts`: `formatStats` ставит звёздочки у статов класса из полного списка из девяти; `formatState` добавляет `classLine` после HUD.
- `src/tools/register.ts`: `structuredContent` инструментов получает `class: { name, shares: [{ id, name, percent }], stats } | null` (одним общим местом, `dataOf`).

## 5. Тексты

| Ключ | en | ru |
|---|---|---|
| `class.architect` | Architect | Архитектор |
| `class.tester` | Tester | Тестировщик |
| `class.guardian` | Guardian | Страж |
| `class.optimizer` | Optimizer | Оптимизатор |
| `class.cleaner` | Cleaner | Уборщик |
| `class.bug-hunter` | Bug Hunter | Охотник за багами |
| `class.test-architect` | Test Architect | Тест-архитектор |
| `class.hybrid` | {a} + {b} | {a} + {b} |
| `class.line` | Class: {name} ({shares}) | Класс: {name} ({shares}) |
| `class.share` | {name} {percent}% | {name} {percent}% |

Доли в строке — через « · » от большей к меньшей, округление до целого процента; показываются все ненулевые.

## 6. Ошибки и граничные случаи

- Данные события неверного типа (`difficulty: 7`, `category: 5`): квест не учитывается в классах (нет веса), подсчёт не падает.
- Сложность неизвестна (`difficulty` нет или не из четырёх): квест не учитывается.
- Журнала нет или в нём нет таких квестов: класса нет, вывод как раньше.
- Гибрид на границах: ровно 60% от основного и ровно 20% от всего — гибрид; чуть меньше — нет.
- Все квесты одного класса: класс без гибрида, доля 100%.
- Проценты в строке могут не давать в сумме 100 из-за округления; это нормально.

## 7. Тесты (TDD)

1. `classOf`: вес по сложности, доли, порог в 3 учтённых квеста, дубли по `id`, неизвестная категория и сложность, ничья, один класс, гибрид на границах 60% и 20%, Test Architect в обоих порядках, третий класс не входит в название, события без `seq`.
2. `className`/`classLine` на ru и en, округление долей.
3. `formatHud`: без класса вывод не меняется; с классом — суффикс и звёздочки только у статов класса из HUD; гибрид — звёздочки обоих. `formatStats`: звёздочки у всех статов класса из девяти.
4. Движок: после нескольких закрытых квестов `view.playerClass` заполнен, до порога — `null`; быстрый путь и полный цикл дают одно и то же.
5. `get_project_state` через MCP-клиент: строка класса и `structuredContent.class` с классом и без.
6. Каталоги: у каждого ключа `class.*` есть ru и en с одинаковыми плейсхолдерами.
