MCP-сервер, который **превращает настоящую разработку в RPG**. У каждого проекта свой уровень (1-50), XP, девять
статов и доска квестов, которые строятся по реальному состоянию кода: мёртвые файлы, модули без тестов, ключи в коде,
нет обработки ошибок, TODO. Ты правишь код, сервер проверяет его машиной, и только потом начисляется XP.

Внутри нет LLM. Сканер, квесты, XP и проверки детерминированы: один и тот же проект всегда даёт одну и ту же доску,
а слова ИИ для награды недостаточно.

Проверено на Windows и Node 22. Другие системы не проверялись.

| | |
|---|---|
| **Квесты из реального кода** | Сканер читает проект (JS/TS и Python; у магазинов и Telegram-ботов свои правила) и превращает находки в квесты: Easy, Medium, Hard и Epic с подзадачами. |
| **XP только после проверки** | Квест закрыт, когда сканер больше не находит проблему. Если ещё и тесты со сборкой проекта прошли зелёными, награда полная, иначе 80%, а недостающее платится один раз после зелёного прогона. |
| **Прогресс у каждого проекта свой** | Уровень, XP, журнал и квесты лежат в отдельной папке на проект. Сменил проект — сменился герой. |
| **Статы, классы, боссы** | Девять статов (Architecture, Testing, Security, Performance, Clean Code, Reliability, Maintainability, Bugs, Tech Debt), шесть классов с гибридами, боссы из скоплений проблем, 12 достижений. |
| **История** | Лента вех по дням: выполненные квесты, побеждённые боссы, достижения, новые уровни. |
| **Русский и английский** | HUD, доска, квесты и причины переключаются одной настройкой. |
| **Безопасно по устройству** | Сканер только читает файлы. Команды проекта запускаются лишь после твоего разрешения для этого проекта. |

## Установка

Нужны Node.js 22.12+ и Git. В npm сервер пока не опубликован: он собирается из репозитория.

```bash
git clone https://github.com/aleks-fw/rpg-game-code.git
cd rpg-game-code
npm ci
npm run build
```

### Подключение к Claude Code

```bash
claude mcp add codequest --scope user --env CODEQUEST_HOME=<папка данных> -- node "<путь>/rpg-game-code/dist/cli/index.js" mcp
```

`CODEQUEST_HOME` — где хранится прогресс (по умолчанию `~/.codequest`). После каждой пересборки MCP-сервер нужно
перезапустить.

### Подключение к другим клиентам (Claude Desktop, Cursor, ...)

```json
{
  "mcpServers": {
    "codequest": {
      "command": "node",
      "args": ["<путь>/rpg-game-code/dist/cli/index.js", "mcp"],
      "env": { "CODEQUEST_HOME": "<папка данных>" }
    }
  }
}
```

### Если ты ИИ-агент

Прочитай [llms-install.md](llms-install.md): там шаги и то, о чём нужно спросить пользователя.

## Быстрый старт

Открой проект в ИИ-клиенте с подключённым CodeQuest и пиши обычными словами:

1. **«Покажи доску квестов»**: сервер просканирует проект и выведет квесты со сложностью и XP.
2. **«Возьми квест 2»** (или выбери на доске): квест уходит в работу, ИИ читает его файлы и правит код.
3. **«Проверь квест»**: сервер сканирует заново. Если проблема исчезла, начисляется XP, обновляются уровень и статы.
   Если нет, он скажет, какое условие ещё не выполнено.
4. **«Разреши команды»** (по желанию): проверка заодно запустит тесты и сборку проекта, и квест оплатится на 100%, а
   не на 80%.
5. Осмотреться: **«мой уровень»**, **«история за неделю»**, **«достижения»**, **«боссы»**.

Нет ИИ-клиента? Тот же цикл работает в терминале: `node dist/cli/index.js board`, стрелками выбери квест, возьми
его, поправь код, нажми `V` для проверки (см. [В терминале](#в-терминале)).

## Как это работает

```
 скан проекта ──► находки ──► квесты ──► ты правишь код ──► проверка ──► XP, уровень, статы
      ▲                                                          │
      └──────────────────── новый анализ ◄────────────────────────┘
```

1. **Анализ.** Сканер строит снимок: находки со стабильными ID и факты о проекте (файлы, тесты, скрипты). Если проект
   не менялся, повторно он не сканируется.
2. **Квесты.** Находки одного вида становятся одним квестом, связанные — эпиком с подзадачами. У квеста есть сложность,
   категория и условия закрытия.
3. **Проверка.** `verify_quest_completion` заново проверяет условия. Квест засчитан, только если находки действительно
   исчезли. Каждая находка оплачивается один раз.
4. **Прогресс.** XP: Easy 100, Medium 300, Hard 500, Epic 1200, на любом уровне одинаково. Каждый уровень стоит на 50 XP
   дороже предыдущего (500, 550, 600, ...), максимум 50-й. Формулы — в [docs/formulas.md](docs/formulas.md).

Команды проекта (тесты, сборка) запускаются только после `set_project_settings` с `allow_commands` и только когда ты
просишь проверку, а не в фоне.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `get_project_state` | Всё сразу: уровень, XP, статы, класс, открытые квесты. |
| `get_player_level` | Уровень, титул, XP до следующего. |
| `get_project_stats` | Девять статов и причины их значений. |
| `get_active_quests` | Доска квестов проекта. |
| `get_quest_details` | Условия, подзадачи и файлы одного квеста. |
| `start_quest` | Взять квест в работу. |
| `verify_quest_completion` | Кнопка «Проверить квест»: перепроверить один квест или все открытые и выдать XP. |
| `refresh_project_analysis` | Просканировать проект заново. |
| `get_project_history` | Вехи по дням (1-365 дней). |
| `get_achievements` | 12 достижений и твой прогресс. |
| `get_project_bosses` | Активные боссы с HP и квестами против них, а также побеждённые. |
| `set_project_settings` | Разрешить или запретить запуск команд проекта. |
| `set_language` | `ru` или `en`. |

Промпты для меню `/` в клиентах, которые их показывают: `quest_board`, `verify_quest`, `work_on_quest`.

## В терминале

Тот же движок работает и без ИИ-клиента:

```bash
node dist/cli/index.js hud            # уровень, XP, статы
node dist/cli/index.js hud --minimal  # одна строка: ◆ УР. 3 · КОДЕР · 1,450 XP
node dist/cli/index.js board          # доска на весь экран: выбрать, взять, проверить
node dist/cli/index.js verify [quest] # кнопка «Проверить квест»
node dist/cli/index.js refresh        # просканировать и показать, что изменилось
node dist/cli/index.js lang ru        # сменить язык
```

Все команды принимают `--path <проект>` и `--home <папка данных>`.

**Доска, которая не мешает.** Запускай `board` в отдельной вкладке терминала, например задачей VS Code, которая
стартует при открытии папки и не забирает фокус ввода: в другом терминале можно спокойно работать. Однострочный
`hud --minimal` подходит для строки состояния Claude Code (`statusLine` в `settings.json`).

В панели ниже 10 строк (или с `board --compact`) доска рисует только две строки: статус и квест под курсором, на месте и
без захвата экрана. Клавиши те же.

## Статы, классы и боссы

- **Статы.** Шесть статов здоровья падают от открытых находок (большой проект прощает больше), Testing растёт с
  покрытием и зелёными прогонами тестов, Bugs и Tech Debt — простые счётчики.
- **Классы.** Класс зависит от того, какую работу ты подтвердил проверкой: шесть классов и гибриды, у определяющего
  стата стоит звёздочка.
- **Боссы.** Семь тем (Dark Forest — модули без тестов, Graveyard — мёртвые файлы, Clone Army, Secret Leak, Blind
  Spots, Breach, TODO Swamp). Скопление находок порождает босса; исправишь все — победишь. Правило, которое не
  отработало, победой не считается.

## Безопасность

- Сканер читает проект и никогда не пишет в него.
- Команды проекта запускаются только с твоего разрешения для этого проекта, с таймаутом и низким приоритетом.
- Прогресс хранится вне проекта, в `CODEQUEST_HOME`; блокировка не даёт двум сессиям испортить данные.
- Секреты, найденные сканером, в выводе маскируются.

## Известные ограничения

- Не опубликован в npm; собирается из исходников.
- Проверено только на Windows и Node 22.
- Сканер знает JS/TS и Python; на других языках доска меньше.
- Команды чужих проектов (`npm test`, `pytest`) проверялись только на тестовых проектах.
- Сообщения правил сканера и вывод команд остаются на английском.
